## 0. 이미 모두가 지키는 것 (그대로)

- 공개 저장소: 책·교재·자막·말뭉치·영상 **출처 이름·원문 문장 금지**. 빈도·순위·커버리지 통계만 쓰고 문장은 전부 자체 제작, 한국어도 자체 번역.
- 한국 화자 한정(한국어 직관 기반). 화자 A = 학습자, B = 현지인(필요하면 C·D).
- 생성은 Claude 세션이 직접 작성. 프롬프트·검수 기록은 파일로 남긴다(이번부터).

## 0-1. 최우선 원칙 (사용자 지시 2026-11-02 — 다른 원칙보다 앞선다)

- **그 나라 사람들이 정말 많이 쓰는 짧은 표현(실제 구어 덩어리)을 회화에 많이, 반복해서 넣는다.** 말뭉치 상위 구어 표현(일본어라면 ちょっと·まあ·やっぱり·じゃあ·ほら·よし·なんか·だって·とりあえず·マジで·やばい 류, 언어마다 native top80)을 편마다 여러 개 노출하고 레벨이 올라도 계속 재등장시킨다. 이유: 학습자가 이 표현을 배워 입에서 나오는 순간 결제하고 싶어진다 — 이것이 전환의 핵심.
- **요즘 시대에 맞춰 SNS·1:1 채팅·데이팅앱 장면을 많이 넣는다**(DM·댓글·메신저 말투·이모지·짧은 답장·읽씹·매칭·약속 잡기). 도메인 7 안에서 친구·사랑 도메인의 비중을 높이고, 생활·일·여행 도메인에도 채팅 편을 둔다. 수위는 §10 그대로.
- 다른 조항(턴 수·길이·반전·주제 구조 등)은 이 둘을 해치지 않는 범위에서 적용한다.

## 1. 회화 생성 축 = 학습목적 9 × 도메인 7 (Q2)

- 목적: travel · exam_jlpt · exam_other · study_abroad · work_japan(각 언어의 '현지 취업') · media · reading · love · making_friends.
  도메인: 생활 · 친구 · 사랑 · 일 · 학업 · 문화콘텐츠 · 여행. (`LEARNER_PROFILE.md`)
- **한 회화가 여러 칸에 쓰이는 것을 인정**한다 — 같은 회화에 `purpose[]`·`domain[]` 태그를 여러 개 달아 최대한 공통으로 쓴다(63칸을 전부 따로 만들지 않는다).
- 기존 연애·데이팅 서사는 `love` 도메인(+ 해당 목적)으로 태그해 그대로 살린다.

## 2. 레벨 = 절벽 구간 R1~R4, L 폐지 (Q3)

- 회화의 레벨은 그 언어의 절벽 구간. 회화 어휘·문법은 **그 구간까지의 누적 목록 안**에서(R1 회화 = R1 단어만). 화면 표시는 초급 = R1, 중급 = R2, 고급 = R3·R4.
- L1~L4 서사 레벨은 쓰지 않는다. 기존 L 데이터는 어휘 상한으로 R 을 산정해 다시 태그.

## 3. 턴 수 (Q1) — 구간별 차등

- R1 6~8턴 · R2 8~12턴 · R3·R4 12~16턴. 한 편 = 장면 하나. 긴 이야기는 편을 이어 가고 다음 편 떡밥은 마지막 턴에.

## 4. 턴 길이 (Q9) — 언어별로 정한다

- 각 앱이 자기 언어 기준(단어 수·음절 수)을 정해 검사기에 넣고 문서에 적는다. R1 에서 1단어 단답은 금지(모든 언어 공통).

## 5. 말투 (Q4) — 관계·장면에 따라

- 낯선 사이·거래·일 = 존댓말/존칭, 친구·연인 = 반말. 사이가 가까워지는 전환 장면을 넣어 가르친다. 한국어 번역도 같은 말투.

## 6. 학습자 성별 (Q5)

- 프로필에서 학습자 성별 선택. 성별로 말이 바뀌는 언어(th·hi·ar·vi 등)만 규칙 치환으로 성별판을 만들고, 나머지는 한 판.

## 7. 읽기 표기 (Q6)

- **모든 턴에 한글 독음 필수**(rd). 언어별 독음 표기표를 문서로 두고 스크립트가 검사한다. 로마자·병음·가나는 보조(외국어 UI·토글).

## 8. 번역·설명 언어 (Q7)

- 콘텐츠(번역·note)는 **한국어 고정**. 표시 언어(ko/en/ja/zh)는 UI 문구만. 예외: 한국어앱(ko)은 영어권 학습자 대상이라 영어 설명 유지.

## 9. 반전 (Q8)

- **모든 편에 의외성 턴 1회**(말실수+정정 · 갑작스러운 감정 · 의외 사실 · 카오스 중 하나). `twist` 태그로 표시, 위치는 본론 후반.

## 10. 수위 (Q12) — iOS App Store 연령 등급 기준

- 앱의 App Store 등급(언어앱 공통 목표 **12+**)을 넘지 않는다: 성적 묘사·누드·불법 권유·미성년 대상 금지, 가벼운 성숙 주제(설렘·질투·말싸움·술 언급)는 드물게. 해당 턴에 `flags[]`(alcohol·profanity_mild·jealousy·haggle 등) 표시.

## 11. 방언·변이 (Q11) — 변이마다 별도 파일

- 앱마다 기본 변이 하나(vi 남부, ar 이집트 구어, pt 유럽, es 카스티야, zh 북방, mn 할흐…)를 문서에 고정. 다른 변이는 **별도 파일**(zh `north/`·`south/` 식 폴더 분리). 턴 안에 병기 필드(id 의 ms)는 쓰지 않는다 → id 는 ms 를 별도 파일로 분리.

## 12. 스키마 (Q13) — 앱마다 그대로, 변환기만

- 저장 형식은 앱별로 유지. 공용 DB(`talkverse-db`)·사이트로 내보낼 때 변환 스크립트가 공통 모양 {num, speaker, tl, rd, ko, note, tags, twist, flags} + 편 메타 {purpose[], domain[], region, scene, variant}로 바꾼다. 템플릿 잔재(칸 이름 `es`, `¡Hola!`, `PRINCIPIANTE 1`, `_meta lang "de"`)는 각 앱이 정리.

## 13. 검수 (Q10) — 그록·제미나이 검수

- ① 스크립트 자동 검사(턴 수·길이·구간 어휘 초과·호칭 일관·독음 표기) → ② **Grok + Gemini 교차 검수**("지적만, 수정 금지", 항목별 개수 출력) → ③ 지적 반영 → 원어민 검수 전까지 `draft` 태그. 프롬프트·결과는 repo 에 파일로 남긴다.

## 14. 문서 위치 (Q14)

- 이 원칙의 게시본 = **talkverse.uk**(공개 페이지). 바뀌면 사이트를 고치고 각 세션에 알린다. 각 앱 repo 에는 링크 + 자기 언어 특이점(독음 표기표·턴 길이·변이·성별판 규칙)만.
